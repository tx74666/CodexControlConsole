# Image manager

Open **Steamwork → Image**, in the position previously occupied by Asset Log / Steam asset checklist. Image replaces that checklist with image browsing, Inbox review, options and directional synchronization. Configuration and saved Inbox review remain collapsed until needed; checking or importing pictures opens their review. A single available option does not repeat its thumbnail beside the main preview. The separate Document row and Promo Art-adjacent shortcut have been removed; the existing standalone URL remains compatible. Opening the panel reads the saved catalogue; scans and synchronization run when requested.

Choose an existing local image folder and a native Notion folder. The local folder holds the library; its `inbox/` accepts new pictures. Dragging files onto the page stages their original bytes in an inbox batch. PNG, JPEG, WebP, GIF, BMP, TIFF and ICO are supported. An optional separate folder can be used for an additional device or mounted drive.

**Check images** creates a persistent review plan without replacing originals. Byte hashes detect identical files, decoded pixel hashes detect identical static pictures in different formats, and matching titles plus real image dimensions identify replacement candidates. Animated pictures use byte identity and title/dimensions. A title or dimension match is a candidate for review, not proof of identical content. Existing filenames stay intact when indexing. New imports use `Title - WIDTHxHEIGHT.ext`, derived from the decoded format and dimensions.

Choose **replace**, **keep existing**, or **save separately** for each candidate, then confirm once. Replacements retain the original bytes under `.image-manager/history/`. Cross-format replacements use the incoming picture's actual extension and archive the previous format. Files and folder identities are checked again at the write boundary; stale plans cannot overwrite later changes. Completed plans have durable receipts, and safe local restoration refuses to overwrite subsequent edits. The page can restore pending plans and selections after reload.

The library groups pictures by purpose/title, then offers every available size and option. Different content with the same purpose and size can be **kept as another option**; identical content is labelled a copy. **Option information** edits the purpose, option name and an explicitly chosen source picture without changing the original file or its name. A different size alone does not establish a derivative. Missing remote source pictures remain pending links until their exact content is available. The title `Togo` displays as **透明Logo** (transparent logo); `Logo` remains a separate purpose unless the user explicitly groups it.

Option annotations stay in the existing local catalogue, keyed by original-file SHA-256. In-place image updates keep the known purpose and option slot; separate imports can create new options. Notion synchronization retains a versioned, small catalogue attachment alongside native originals so purpose, options and derivative references can return without uploading the same image again. The selected source determines metadata updates; previous catalogue versions remain available. Images and catalogue attachments are verified separately.

**Sync** uses a selected source and destination. A conflict-free batch of new images may be added by that click; replacements require the review choices. Reading errors remain visible. Device synchronization uses the same review and original-byte copying.

Notion synchronization starts a dedicated, short-lived, signed-in Codex app-server connection only when requested. It makes fixed Notion tool calls without starting a model turn, extracting credentials, or scheduling a monitor. Each call is restricted to the configured Notion folder and its returned original-file references. Availability and a verified connection are shown separately.

Uploads append native Notion file attachments, retain previous remote versions, and are complete only after downloading the attached original and matching its size and SHA-256. Exact duplicates already present are skipped. Uncertain upload or attachment receipts are retained for review and are never silently retried. Downloads enter the local inbox review workflow. A sync record's completed transfer and a pending local replacement are distinct states. Previously attached originals and catalogue files with complete verification evidence can be rechecked only within the same request and scope; this reads and verifies the existing originals and catalogue without uploading or attaching them again.

Notion transfers currently accept at most 50 originals per batch and 20 MiB per original; originals are not resized. Local imports accept 64 MiB per original and 96 MiB total per batch. Configuration and private synchronization receipts live in the existing Console user-data directory; the local catalogue and plans live in the selected folder's `.image-manager/`. No personal folder paths or Notion page IDs belong in release defaults.

Validation: `python tools/check-image-manager.py`, `python tools/check-image-manager-http.py`, `python tools/check-image-manager-notion.py`, `node tools/check-image-manager-ui.mjs`, and the existing desktop management-entry and package checks. Integration checks use disposable libraries; real original-file transfer verification is a separate acceptance step.
