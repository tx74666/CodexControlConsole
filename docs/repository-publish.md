# Console 多仓库提交与推送

入口只在桌面 Console 标签页：`提交并推送`、`配置`和简短状态。
配置默认关闭。仓库、命名、说明预览、执行详情与单库重试都在配置内按需显示。
设置自动保存；尚未保存或格式错误的配置不会触发上传。

## 日常使用

1. 保存工作文件。
2. 进入 Console，点击一次 `提交并推送`。
3. 各启用仓库串行处理。失败的仓库保留原工作和提交，其他仓库继续。

初次配置复用开发者源码绑定、Blender 仓库绑定和 Work 工作区。
核对真实 Git 根目录、读取与推送地址、实际当前分支。
未找到本地路径的仓库保留为未启用配置，填写路径后再启用。
仓库数量不固定；可以添加、停用仓库并修改其独立目标分支。
不会替用户切换分支。

## 提交说明

默认标题使用该仓库或改动组件的当前权威版本原值。
例如版本来源为 `1.6.41`，标题就是 `1.6.41`。
不会因点击按钮递增版本、修改版本文件、建立 Tag 或发布 Release。
同一版本可以重复提交。

第二个预设为改动插件／模块名称和对应当前版本。
多个独立组件各自读取实际版本；不能确定单一版本时，使用已保存的备用标题，
默认 `更新进度 {datetime}`。版本明细、可选副标题与备注放入正文。
文件摘要只描述实际新增、修改、删除的文件，不从二进制变化猜测功能修复。
本地规则独立可用；没有新增 AI 服务、模型或密钥配置。

## 工作文件同步

只有明确保存的同步映射参与操作，先同步再判断 Git 变化。
沿用 Blender `tools/build_sources.json` 的依赖文件顺序，最后将已保存的
`Builder6.blend` 同步到仓库 `Build.blend`。
来源缺失、读取／复制期间变化、目标被其他程序改写或清单损坏时，暂缓该仓库。
已经复制的工作文件保留在工作树，失败不会回滚用户文件。

提交使用正常 Git 暂存、提交与推送，保留 `.gitignore`、LFS、过滤器和 Git hooks。
通用流程不套用 Console 开发者更新的源码白名单。
私人记录、凭证和缓存仍排除，也可配置附加排除范围。

## 保护与恢复

操作前检查远端真实分支。远端领先、分叉或操作中变化时，暂缓而不自动合并、
强推、重置或隐藏工作文件。
未完成合并／变基、已有暂存选择、已知 Codex／Work 正在编辑、活动状态无法核实，
以及提交时文件、分支、配置或索引变化，都会保留原状态并给出简短原因。
已有暂存选择采用保守策略：无论全量或部分暂存，都留给原操作者处理。

没有文件变化但已有本地提交时，只推送原提交，不改其说明。
提交成功后推送失败，原提交与目的地写入持久记录；下一次主按钮或单库重试
先核验并继续该提交，不再创建一份。
超时或回执不明确时，只有实际远端包含原提交才报告成功；无法核验显示待核验。
修改配置不能把未完成提交悄悄发送到另一仓库或分支。

浏览器在发送前持久保存请求编号与范围，后台对重复编号幂等处理。
刷新和重启只恢复回执，不自动重新发送。
后台明确确认某请求不存在时，详情提供用户触发的 `继续原请求`，保留原编号和范围。
其他仓库成功结果不会因单库失败回滚。

## 验证与触发范围

关键流程通过临时本地 bare 仓库、实际 HTTP 权限边界和隔离 DOM 场景验证。
测试模式只能访问临时目录中的本地远端；不使用真实仓库上传测试。
真实批量同步、提交、推送仅由用户点击主按钮或明确的单库重试触发。
初次发现、打开配置和说明预览不执行工作文件同步或网络推送。
