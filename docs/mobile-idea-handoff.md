# 手机想法带到电脑

手机公开入口的长期想法保存在原有 PhoneStore，电脑想法保存在已配对 Console 的原有私有数据库。两者属于不同浏览器来源；“连接电脑”本身不会搬移手机内容。

在已保存想法中点“带到电脑”，只交接这一份保存稿。正文、原图、长期要点、执行稿和归档状态一起传送，手机副本继续保留。未保存编辑先保存，不把其它讨论草稿或其它想法附进去。交接只保存内容；日后交给 Codex 时仍进入实际工作区与执行范围的最终审核。

公开页面在点击内建立自己的电脑窗口，再以准确窗口、来源及随机通道标识交换消息。电脑窗口完成原有配对后，用自己的同源请求和 HttpOnly 配对 cookie 接收内容。配对凭据不传给公开页面；不扩大 plan-sync 权限，也不开放跨站工作 API。浏览器不能保留新窗口或 opener 时，可以从想法的更多菜单生成完整 `.console-idea` 包，再在已配对的电脑页面选择该包导入。包包含同一冻结正文、执行稿和原图；生成下载链接不等于实际保存文件或电脑已经导入。

实际接收使用有限 multipart 请求：`requestId` 与 `text` 两个字段，文字字段是最长 80,000 UTF-8 字节的单条 JSON 描述，最多四张原图，每张不超过 8 MiB，整个请求沿用 24 MiB 限制。超过限制拒绝整份内容，不截取图片。电脑核对图片原始字节的 SHA-256、格式和大小，再在同一数据库事务保存正文、附件、来源和回执。

描述格式如下；这些来源字段是资料的来历，不是发送、执行、模型能力或项目权限。

```json
{
  "format": "codex-console-idea",
  "version": 1,
  "source": {"clientId": "来源储存的持久 UUID", "ideaId": "32位想法标识", "revision": 1},
  "idea": {"title": "标题", "body": "正文", "executionDraft": "执行稿", "archived": false, "keyPoints": []},
  "images": []
}
```

来源储存 UUID、临时通道标识与导入请求 UUID 各有用途。已尝试交接会冻结原 UUID、完整描述和原图，并绑定当时的电脑入口。结果不明时，“核对上次交接”只查这个原请求的实际回执，不再次导入，也不转往另一个电脑入口。手机后来修改的内容仍保留，原版本核对成功不表示手机新版本已同步。尚未尝试交接的保存稿可生成完整包；不能借导出解锁未知结果。同一来源版本的不同内容会被拒绝。手机新版仅在电脑内容仍等于上次交接版本时更新原想法；电脑已经编辑则提示冲突，保留两端内容，旧版不能覆盖新版。

“已带到电脑”必须来自实际服务器回执，并核对来源、请求与真实电脑想法／记录身份。超时或回执不明保留冻结请求，不自动发送 Chat、不代替用户执行，也不伪造完成。iPhone 的新窗口、文件选择、键盘和后台表现需要实体设备验收；隔离浏览器结果不能作为实机结论。

普通 Chat 的常驻事件转发器及实际极速／高／Pro 回执是另一段尚未接通的链路。想法交接成功不能作为聊天已自动发送或已完成 Workspace 修改的证明。
