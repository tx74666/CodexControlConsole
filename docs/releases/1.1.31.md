# 1.1.31

Console prepares files larger than 100 MB for Git LFS before committing and uploading, while retaining the original working files, exclusions, staging choices and existing hooks. The staged LFS pointers are checked against the source size and hash, and uploads use standard Git LFS followed by the normal Git push.

New commit subjects and repository version labels show only the target version, such as `1.6.50`. Historical transition subjects remain readable, and version preparation still follows the same source and retry checks.

Existing outgoing commits containing ordinary large blobs require a separate history check; adding a tracking rule alone does not remove those objects. Console reports this condition without silently rewriting history or force-pushing.

The storage regression uses the production path-containment function so Windows temporary-directory aliases do not cause a false release failure.
